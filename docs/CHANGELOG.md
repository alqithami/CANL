## Internal audit of v5 (second pass before delivery)

* **Pod plans lost their preparation jobs** (critical): `scripts/make_pod_plans.py` aliased the stage
  dicts of the source plan, so editing pod A's `prepare_models` emptied pod B's and vice versa. The
  generator deep-copies stages, refuses to write a plan with an empty matrix list, and both plans are
  regenerated (`tests/test_plan_and_report.py::test_complete_8gpu_plan_and_pod_split_are_consistent`
  regenerates and checks them). `validate_plan` now rejects empty matrix lists, stages that expand to
  zero jobs and `parallel`/`gpu_share` < 1 or non-integer.
* **Failure isolation** (major): a failed stage no longer halts the whole campaign. Its dependants
  (transitively, `aggregate` included) are marked `blocked`, independent stages keep running, the exit
  code is 1 and the failed/blocked stages are listed; `--fail-fast` restores stop-everything.
* **Campaign lock and stale jobs** (major): `<root>/.runner.lock` (`flock`) makes a second runner on
  the same root exit with code 2; a job left in `status: running` by a dead runner is recognised
  through its pid and restarted, a live one makes the runner refuse to start. SIGTERM/SIGINT terminate
  the children. With several CUDA devices visible `--gpus` is mandatory (exit 2).
* **Report refresh**: rebuilt in a background thread after each validated stage; new launches wait for
  it so that a failing report stops the campaign before another job starts (test adjusted); a refresh
  requested while one is running is deferred, not dropped; the CPU smoke exercises the partial-campaign
  refresh (`report_after_each_stage: true`).
* **Scheduler placement**: best-fit placement of shared jobs (pack partially used cards), whole-GPU
  stages are not starved by `gpu_share` stages, `CAENL_PARALLEL` is capped by the real concurrency
  (`min(parallel, n_gpus × gpu_share)`), `parallel: 0` is treated as 1.
* **torch-fidelity reference cache** (major): the DDPM prepare step warms the cache with the metric set
  the jobs request (FID + KID + IS ⇒ `features-2048`, `features-logits_unbiased`, `stat-fid-2048`);
  the per-job lock guard checks those exact files instead of a substring match, and the prepare step
  fails if any is missing.
* **ViT weight decay**: `class_token` / `pos_embedding` (and 1-d tensors) are excluded from weight
  decay in `Trainer.make_optimizer` (DeiT / MAE recipes); covered by `test_layer_decay_param_groups`.
* **Kaggle script**: the free-space check applies only to what is still needed (download vs
  extraction), an incomplete or unreadable archive is removed and fetched again, 7z/unzip presence is
  checked.
* Docs: honest `--no-resume` semantics (re-queues succeeded jobs; each job still restarts from its
  checkpoints; delete the job directory to recompute), failure-isolation and lock semantics in
  README/RUNBOOK/CLI help. Package version 5.0.0.

# v4 — response to the pre-campaign review ("do not start the paid campaign yet")

Every blocker of the review maps to a change below. Section numbers refer to the review's list.

## 1. Full MACC credit assignment (blocker) — `src/caenl/core/controllers.py`, `vision/train.py`, `vision/task.py`
* The acquisition action (τ) is no longer rewarded with the next controller step's ΔVal. `acquire()`
  records the controller value *before* the round and registers a **pending acquisition action**
  (τ, number of queries, step); after a pre-registered number of post-acquisition steps
  (`full_macc.acquisition_reward_steps`, 200 CIFAR / 1,000 ImageNet-1K) the trainer measures the value
  again and rewards exactly that action with 10·ΔVal − β·n_q through the quantile head only.
* Pending actions (both kinds) and the acquisition reward baseline are part of `state_dict()` and
  therefore of every round checkpoint; `new_phase()` drops only the regularisation pending action.
* The quantile head is disabled (`quantile_head_enabled=False`) for tasks without acquisition.
* Tests: `tests/test_core.py` (credit assignment, persistence, explored actions excluded, quantile
  head disabled) and `tests/test_integration_full_macc.py` (straight vs interrupted-and-resumed job:
  identical selections, λ, τ, accuracy, acquisition rewards).

## 2. Multi-seed ImageNet-1K production plan (blocker) — `configs/plans/franklin_imagenet1k_revision.yaml`
* ResNet-50, six paired seeds, 224 px (256 px cache, RRC-224 train / centre-224 test), 10 → 60 % labels,
  20 epochs per round, one frozen schedule; methods: full supervision, random, entropy, CoreSet, BADGE,
  Noise Stability (AAAI 2024, documented independent reimplementation — `docs/BASELINES.md`), CÆNL
  acq-only, random + fixed DCR, CÆNL + fixed DCR, CÆNL + MACC-Lite, CÆNL + Full MACC; ViT-B/16 confirmation
  with three paired seeds; `aa_sanity` stage (torchvision ResNet-50 must give ≈ 76.1 % / ≈ 0 %).
* Honest compute statement in the plan header and `docs/RUNBOOK.md` (≈ 995 A100-h, ≈ 5.5 days on 8 GPUs,
  ≈ US$1,600–2,000; ResNet-50 only ≈ 560 A100-h).
* Loader: ImageNet-1K in class-folder / flat-val+CSV / Kaggle layouts (`resolve_imagenet_layout`), 256 px
  uint8 cache served from a **memmap with a background prefetcher** when it does not fit in RAM
  (`DeviceArray` memmap mode, order-preserving, tested); ViT patch grid follows the training resolution.
* AutoAttack subset for ImageNet-1K: fixed class-stratified 5,000 images (RobustBench convention),
  identical across methods/seeds, saved per job (the previous code evaluated the first *n* test images,
  which are class-sorted on ImageNet — fixed for every dataset).
* `full_1gpu.yaml` → `supporting_1gpu.yaml`, relabelled as supporting (CIFAR/ImageNet-100); `tier_c`
  removed; `parallel: 1` everywhere.

## Internal audit of v4 (second pass before delivery)
* **Plan precedence bug (would have silently run the GPU smoke with the protocol's 100-epoch CIFAR
  schedule):** protocol dataset/arch overrides were merged *after* plan defaults and stage job blocks.
  Order is now protocol → dataset override → arch override → plan defaults → stage job → per-method
  overrides (regression test `test_plan_defaults_override_protocol_dataset_overrides`).
* **Host-RAM budget:** `DeviceArray` used the host's physical RAM to decide whether to copy a dataset into
  pinned memory — on a 2 TB pod eight parallel jobs would each have copied the 252 GB ImageNet cache.
  The budget is now min(RAM, cgroup limit) × fraction / `CAENL_PARALLEL` (exported by the runner), arrays
  are built chunk-wise without a 2× transient, and `imagenet1k` is forced to the memmap path.
* **Prefetcher:** a worker exception no longer leaves the consumer blocked forever (error sentinel,
  re-raised in `get()`); queues are bound per schedule; `np.take(mode="clip")` avoids a double copy.
* **Preflight:** torchvision ResNet-50 weights are probed at their real URL and fetched with `--download`;
  the disk estimate (≈ 400 GB for the production plan) matches the documented volume size.
* **AudioCaps acquisition** runs in its own late stage (supporting plan and GPU smoke), so a blocked
  YouTube access cannot hold up the vision/language/diffusion results; cookies / extra yt-dlp arguments
  via `CAENL_YTDLP_COOKIES` / `CAENL_YTDLP_ARGS`; loosely named local files are accepted only if they are
  ≈ 10-s segments; partial downloads are cleaned on timeout.
* **Full MACC reward clipping:** validation deltas are clipped at ±2 nats (`reward.value_delta_clip`)
  so that a transient loss blow-up cannot swamp the policy baseline (inactive in a healthy run).
* Gate/validator details: required vision metrics mirror the task's defaults (`also_final`, `pgd_steps`,
  corruptions off by default), probes are evaluated even with the gate off, `caenl report --strict`
  validates the directory it is given, events when a pending acquisition action cannot be rewarded,
  McNemar record complete in the degenerate case, empty validation trees rejected, `python3-venv`.

## Go / no-go
* **No-go for the paid campaign from this sandbox**: it has no GPU, no ImageNet-1K, no AudioCaps audio
  and no Hub access, so the real-data GPU smoke has *not* been run. Everything that can be verified
  without those was verified: 48 unit/integration tests, the full CPU smoke plan (every stage type,
  interruption/resume, gate probe, strict aggregation) — see `docs/sample_smoke_report/`.
* **Go-live criteria on the pod**: `bootstrap_runpod.sh` exits 0 → `caenl preflight --plan
  configs/plans/franklin_imagenet1k_revision.yaml --download` prints READY → `caenl run --plan
  configs/plans/smoke_gpu.yaml --parallel 1 --gpus 0` finishes with every stage validated, both
  `RESUME_CHECK.json` ok, the AA sanity job and the gate probe behaving → `caenl report --root
  .../smoke-gpu --strict` exits 0 → `bootstrap_runpod.sh --lock`. Only then start the production plan.
